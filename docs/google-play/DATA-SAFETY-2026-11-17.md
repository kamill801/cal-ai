### 제출 전 확인할 한계

- 이용 분석은 계정과 연결된다. 익명 분석으로 선언하지 않는다.
- 분석은 기본 꺼짐이고 철회하면 신규 전송을 중지한다. 철회·로그아웃은 서버의
  과거 이벤트·세션을 지우지 않는다. 자동 서버 만료도 구현되어 있지 않다.
- 모바일/API 속성 allowlist는 서로 다르고 문자열 내용 전체의 개인정보 검열은
  보장하지 않는다. 현재 모바일 호출이 건강 입력·자유 메모를 분석 속성으로
  보내지 않는다는 사실을 모든 로그에 민감정보가 없다는 보장으로 확대하지 않는다.
- 호스팅·인증 제공자의 IP/접속·오류 로그와 보관 조건은 이벤트 코드만으로 확정할
  수 없다. 위치 기능이 없다는 것과 네트워크 IP가 존재하지 않는 것은 다르다.
- 파일명/MIME/크기는 사진 흐름의 metadata다. 이 사실만으로 일반 문서 업로드나
  모든 파일 접근을 주장하지 않는다.
- 실제 광고·결제 SDK 수집은 확인되지 않았다. 체크아웃 버튼 이벤트만으로
  결제정보 수집을 선언하지 않는다. 향후 결제 연결 시 다시 검토한다.

## Console 작업과 승인 경계

2단계 전체/부분 삭제 요청은 같은 공개 URL이며 부분 삭제 ‘예’가 저장됐다.
새 창과 후속 새로고침에서 값을 다시 읽었다. 3단계는 기존 10개 유형이며,
기기/기타 ID는 아직 선택하지 않았다.

‘기타 개인정보’ 저장은 처음 안전 검토에서 차단되어 중단했다. 이후 운영자가
나이·성별의 **필수 수집·앱 기능·맞춤설정 초안 저장**을 명시적으로 승인했다.
이에 수집됨·임시 처리 아님·필수·앱 기능·맞춤설정을 입력하고, 항목 저장 후
페이지의 **임시저장**까지 실행했다. ‘변경사항이 저장되었습니다’를 확인한 뒤
새로고침해 1~4단계로 다시 이동하고 해당 라디오/체크박스의 저장값을 읽었다.

이 과정에서 기존 이름·이메일·사용자 ID의 입력도 페이지 수준에서 저장됐다.
새로고침 후 각 항목을 열어 다음 값을 다시 확인했다.

| 항목 | 저장된 필수성 | 저장된 수집 목적 |
| --- | --- | --- |
| 이름 | 선택 | 앱 기능·애널리틱스·계정 관리 |
| 이메일 | 필수 초안 | 앱 기능·애널리틱스·계정 관리 |

네 항목 모두 수집됨·임시 처리 아님이다. 선택 분석의 실제 동의 조건은 앞의
근거표와 같다. 공유 미선택은 여전히 제공자 검증 전의 잠정값이며 최종
‘공유 없음’ 인증이 아니다. 나머지 여섯 항목은 답변 미완료로 남았다. 최종

## 남은 운영자 결정

1. 나이·성별의 초안 저장 승인은 완료했다. 남은 여섯 항목의 필수/선택·목적과
   세션 ID 추가 분류, 공유 예외를 확정해야 한다. 최종 준수 확인·제출은 별개다.
2. 사진 7일 정리 기준과 다른 종류의 필요 기간/종료 조건, 문의 처리 책임·기한
   확정. 일반 사용자 삭제·자동 정리 활성화는 별도 승인.
3. 실제 제공자의 공유/학습 opt-in, 처리자/국외 이전·로그·백업 조건 확인.
   키나 비밀번호를 채팅에 보내지 않는다.
4. 개인 계정의 건강 앱 적격성 문의는 운영자 승인 후 전송했다.
   케이스 `1-5575000041933`은 Open이며 담당자 답변을 기다린다.
   `GOOGLE-ELIGIBILITY-INQUIRY-DRAFT-2026-11-17.md`에 접수 증거와 자동 안내의
   한계를 기록했다. 계정 전환은 하지 않는다. 기존 계정/비공개 테스트만으로
   예외를 확정하지 않는다.

정책은 건강 앱의 조직 계정 요건을 제시한다. 이번 Console 자동 안내는 일반
영양·운동 앱은 개인 계정 가능하다는 취지였지만 오류 가능성을 명시했다.
담당자 답변과 구분하며, 개인 계정에서 앱 생성/AAB 업로드 성공도 최종 적격성
승인은 아니다. 12명/14일 테스트는 별도 요건이다.
